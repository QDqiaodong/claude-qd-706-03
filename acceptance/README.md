# 锯切批次交接与产出谱系 · 验收手册

## 1. 能力总览

把加工工单从「计划板数 + 手工完成数」推进到「可追溯的逐片实产」：

| 环节 | 后端动作 | 关键约束 |
| --- | --- | --- |
| 开锯建批 | `POST /api/saw-batches` | 冻结荒料 / 工单 / 锯切方式 / 班组 / 计划板数 / 当时排板顺序；首个批次固化工单完成数基线 |
| 逐片登记 | `POST /api/saw-batches/{id}/outputs` | 成品 / 可返切余料 / 锯耗回到同一批次；扫码幂等键去重；大板全库唯一归属 |
| 班组交接 | `POST /api/saw-batches/{id}/handover` | 先完成逐片交接再比对，生成差异，进入「差异待核」；现场记录一条不丢 |
| 差异核清 | `POST /api/saw-batches/discrepancies/{diffId}/resolve` | 确认实际结果 / 更正归属 / 作废，必须填原因，变更前后写留痕 |
| 批次收口 | `POST /api/saw-batches/{id}/close` | 差异全部核清才可收口；悲观行锁串行；固化谱系 + 按合格实产推进工单 |
| 反查 | `GET /api/saw-batches/by-order`、`/trace-by-slab` | 工单看批次/差异/逐片来源；大板反查所属批次与历次更正 |

批次状态机：

```
OPEN 开锯交接中 ──交接无差异──▶ READY 可收口 ──收口──▶ CLOSED 已收口
     └──交接有差异──▶ PENDING_RECONCILE 差异待核 ──差异核清──▶ READY
                        ▲ 交接后补登/更正会自动重算，可回到 OPEN/READY
```

完成数口径（重要）：

```
工单已纳入批次（saw_baseline_count 非 NULL）后：
  done_count = saw_baseline_count + Σ【已收口】批次的 qualified_count
开锯中 / 差异待核 / 可收口但未收口的批次，其产出一律不计入完成数。
qualified_count = ACTIVE 成品片数中等级 ≠ DEFECT 的片数（余料、锯耗不计）。
```

## 2. 唯一性与并发如何兜底

| 风险 | 数据库约束 | 失败方体验 |
| --- | --- | --- |
| 断网重试 / 重复扫码生成两份 | `uk_saw_output_token(batch_id, client_token)` + 批次行锁串行 | 返回首次产出 `duplicated=true`，不新建 |
| 同一大板归两个批次 | 生成列 `active_slab_id` + 唯一索引 `uk_saw_output_active_slab` | **409**，回带先到批次号/顺序/登记人/时间，提示「不能静默覆盖」 |
| 两人同时收口 / 重复点击 | 收口先 `SELECT … FOR UPDATE` 锁批次行，状态 CAS | 后到者 **409** 并回带已收口结果（收口人/时间/合格数） |
| 收口与工单计数半成 | 收口 + 工单 + 荒料在同一事务 | 中途失败整体回滚，不存在「批次收口但完成数没动」 |
| 作废已被引用产出 | 服务层查 `source_slab_id` 返切引用 | **400**，必须先解除引用或走归属更正，不能直接删除 |
| 差异未核清就收口 | 收口前强制 `openDiffCount=0` | **400** 阻断，且差异期间完成数不提前增加 |

## 4. 七组验收怎么跑

一键脚本（只依赖 bash + curl）：

```bash
# 启动系统
./start.sh            # docker compose 起 mysql / backend / frontend

# 等后端就绪后跑验收
./acceptance/acceptance.sh
# 自定义地址：BASE=http://localhost:8080 ./acceptance/acceptance.sh

# 出库发货「加大板」状态闸门验收（只新建 DEL-ACC-* 发货单，不动历史单据）
```

## 4b. 发货单加大板状态闸门（acceptance-delivery.sh）

规则：**只有待装车（LOADING）发货单允许增补大板明细**；已发运 / 已签收 / 已结款在页面和
接口两侧都拒绝，绕过页面直接 `POST /api/deliveries/{id}/items` 也返回 **400**。拒绝后原明细、
总金额、大板库存状态保持不变，历史发货单不被改写。

| 场景 | 期望 |
| --- | --- |
| 待装车正常加板 | 200；明细新增、总金额=Σ面积×单价回写；在库大板→已预定；列表 itemCount / 首页发货金额同步 |
| 重复点击 / 同板重复加 | 400「不能重复加入」；不产生第二行，金额与大板状态不变 |
| 已发运单直连接口加板 | 400；明细数 / 总金额不变；原大板仍已出库、新大板仍在库 |
| 已签收 / 已结款单加板 | 400；同上，历史金额与库存零改动 |
| 刷新后复查 | 列表按状态筛选仍命中各单、状态与金额保持拒绝前值；被拒大板仍在库 |
| 发运与加板并发 | 行锁串行：要么发运先提交加板被 400（大板留在库），要么加板先成功再随单出库；终态确定，不出现「已发运却已预定 / 金额被改写」 |

页面侧：列表中只有待装车行显示可点击的「加大板」，其余状态按钮置灰并悬浮提示原因；
加大板弹窗在单据被其他人推进状态后也拒绝提交（按钮 loading 防重复点击）。

## 4c. 七组验收怎么跑（锯切批次）

### 场景 1 · 计划吻合（锯切批次）
- 看 SB-2026-0001：状态 `CLOSED`，成品 6 / 余料 0 / 锯耗 0，合格实产 6。
- 工单 CO-2026-0009：完成数 6/6、DONE；前端「板数」列显示「基线 0 + 已收口合格 6」。

### 场景 2 · 数量不符（缺号 + 未解释锯耗 + 尺寸超差）
- SB-2026-0002 详情：差异清单 2 条（SIZE_TOLERANCE、UNEXPLAINED_SAW_LOSS），冻结顺序第 6 序显示「缺号」。
- 工单 10 完成数保持 **0**（差异待核不提前计数）。
- 直接点收口被 400 阻断：「还有 N 条差异未核清，批次不能收口」。

### 场景 3 · 跨批次重复
- 把 SB-0003 已登记的 SLB-0301 往 SB-0004 再登记 → **409**，响应 `current` 回带
  `batchNo=SB-2026-0003`、顺序号、登记人、时间；页面弹「先到记录已保留…请做归属更正」。
- 库里 `mill_saw_output` 仍只有 SLB-0301 的一条 ACTIVE 产出（唯一索引保证）。

### 场景 4 · 离线重试 / 重复扫码
- 同 `clientToken` 连续 POST 两次（脚本对 SB-0003 第 7 序新建 SLB-0305）：
  第一次 `duplicated=false`、第二次 `duplicated=true`，返回同一 `output.id`。
- 换新 token 再扫同一 SLB-0305 → 409（幂等键与大板唯一归属是两道独立防线）。

### 场景 5 · 差异更正
- 差异 #4 不填原因 → 400。
- 用 `CORRECT_ASSIGN`（outputId=25 → SB-0005 第3序，必填原因）：
  - SB-0005 差异清零变 **READY**；SB-0006 第5序变缺号回到 **差异待核**。
  - 两批的谱系留痕都出现 `CORRECT_OUTPUT`，含变更前/后。
- 对 SB-0006 补登新大板 SLB-0607 第5序 → 自动重算 → **READY**。
- 被引用保护：SLB-0401/0402 的 `source_slab_id` 指向 SLB-0301/0302，作废来源产出会被拦。

### 场景 6 · 并发收口
- 对 READY 的 SB-0005 同时发两个 close：**一个 200、一个 409**；再点一次仍 409 回带已收口结果。
- 收口后工单 12 完成数 = 0 + 3 = **3**（SB-0006 未收口，不提前计入）。
- 收口 SB-0006 后完成数 3 + 2 = **5**，与计划 5 吻合，工单 DONE、荒料 DONE。
- 已收口批次再登记产出 → 400（谱系固化）。

### 场景 7 · 旧工单兼容
- 工单列表 1~8：口径标签「待补交接」，「完成+1 / 完工」按钮仍在且可用（脚本对工单 2 验证 +1）。
- 工单 9~12：标签「锯切谱系」，手工按钮隐藏，只能走批次收口；批次抽屉列出各批与待核差异。
- 大板详情（左侧树点 SLB-0602 / SLB-0401 等）：显示当前归属批次，反查表格 + 历次更正时间线。

## 6. 为什么「只加工单完成数输入框 / 单独批次列表」不够

- **逐片唯一归属**：靠生成列唯一索引 + 幂等键，独立输入框无法表达「同一板不能归两批」。
- **差异阻断**：缺号/重复号/超差/数量不符/未解释锯耗是交接比对的结果，必须阻断收口与计数。
- **审计留痕**：建批/交接/确认/归属更正（变更前后）/作废/收口全部 append-only。
- **收口一致性**：批次状态、逐片归属、工单完成数、荒料状态同事务提交，失败整体回滚。
